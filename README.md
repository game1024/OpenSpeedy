# 🚀 Features
- Quick speed adjustment
- Modern UI
- Supports both x86 and x64 platform processes
- No kernel intrusion — Ring-3 level hooking, does not tamper with the system kernel
- Silent boot launch (no main window, dialog or notification — tray icon only)
- Auto acceleration for bound games (persisted process + factor/gear, applied the moment the game starts)


# 💾 Installation
📦 **Method 1: Winget**

``` powershell
# Install command
# Specify the exact package ID and source to avoid Microsoft Store name conflicts.
winget install --id Game1024.OpenSpeedy --exact --source winget
```

## ⚙️ Two independent options

Both switches live on the Settings page and can be enabled or disabled independently.

**Silent boot launch** — starts with Windows with the main window hidden from creation: no window, dialog or notification, just the tray icon. Click the tray icon to restore the window at any time; the tray menu can quit the app. It shares the single OS autostart entry with the original "Auto Start" (which shows the window), so the two are mutually exclusive — enabling one switches the other off. The entry always carries `--autostart`, so only boot sessions stay hidden; opening the app manually still shows the window.

**Auto acceleration** — bind a game's process name (Settings → Auto Acceleration, or "Bind with current factor" in the process detail) to a custom factor or one of the five gears. The binding (name, executable path, architecture, factor or gear) is persisted in `auto_accel.json`; gear bindings follow the multipliers defined in the Speed Gears section. From then on, a Rust background monitor polls the process table every 500 ms and injects + applies the saved factor as soon as the bound process appears, with no further selection or confirmation. Acceleration stops when the process exits, the rule is removed, or the master switch is turned off. Because the monitor lives in the Rust process, it keeps working while the window is hidden.

> Note: the speed factor is global to each bridge process. If several bound games run at once, the most recently started one wins. Preferences are stored in `%APPDATA%/com.game1024.openspeedy/` as `boot_launch.json` and `auto_accel.json`.

# 🔧 How It Works

Prerequisites:
- [Node.js](https://nodejs.org/) 18+
- [Rust](https://www.rust-lang.org/)
- [CMake](https://cmake.org/)
- [Visual Studio](https://visualstudio.microsoft.com/) (with C++ desktop development workload)

Build command:

``` powershell
npm run tauri dev
```

OpenSpeedy adjusts game speed by hooking the following Windows system time functions:

| Function | Library | Purpose |
|----------|---------|---------|
| Sleep | user32.dll | Thread sleep |
| SetTimer | user32.dll | Creates message-based timers |
| timeGetTime | winmm.dll | Retrieves system uptime in milliseconds |
| GetTickCount | kernel32.dll | Retrieves system uptime in milliseconds |
| GetTickCount64 | kernel32.dll | Retrieves system uptime in milliseconds (64-bit) |
| QueryPerformanceCounter | kernel32.dll | High-resolution performance counter |
| GetSystemTimeAsFileTime | kernel32.dll | Retrieves system time |
| GetSystemTimePreciseAsFileTime | kernel32.dll | Retrieves high-precision system time |
| SetWaitableTimer | kernel32.dll | Sets a waitable timer |
| SetWaitableTimerEx | kernel32.dll | Sets a waitable timer (extended) |
